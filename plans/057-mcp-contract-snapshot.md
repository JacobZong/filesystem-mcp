## Why this matters

What MCP clients actually consume is the server's advertised contract: tool
names, descriptions, `inputSchema`, annotations, prompts, resource templates,
capabilities and instructions. Regressions in it have escaped before. Issue
#51 (an external user, 2026-10-04) was a `$ref` in `edit`'s published schema
that some clients cannot follow. Two capability-advertising mistakes were
caught only in review (`b53e64e4` "stop advertising subscribe on legacy
HTTP", `f20cd258` "gate listChanged on legacy HTTP"). Today's tests only
spot-check: they compare names, look for `$ref`, check a few fields per tool,
and apply a size budget. A loosened schema constraint (a dropped `maxItems`,
`enum` or `pattern`) or a reworded description passes all of them.

A committed snapshot turns every contract change into a reviewable diff in the
PR, and an accidental one into a red test. Node 24's built-in
`t.assert.snapshot` needs no dependency. (`github/github-mcp-server` commits
per-tool schema snapshots for the same reason.)

## Steps

### Step 1: Write the test

Create `__tests__/contract.test.ts`:

```ts
import assert from 'node:assert/strict';
import { after, before, describe, it } from 'node:test';

import { cleanupTestRoot, createTestClientPair, createTestRoot } from './helpers.ts';

let tmpDir: string;

/**
 * The advertised MCP contract — what every client reads before its first
 * call. A change here is a wire change: review the snapshot diff, then
 * regenerate with `node --test --test-update-snapshots __tests__/contract.test.ts`.
 * Run with no FS_* variables set: the get-help text embeds the max file size.
 */
async function surface(readOnly: boolean): Promise<Record<string, unknown>> {
  const pair = await createTestClientPair([tmpDir], { readOnly });
  try {
    const { tools } = await pair.client.listTools();
    const { prompts } = await pair.client.listPrompts();
    const { resourceTemplates } = await pair.client.listResourceTemplates();
    const help = await pair.client.getPrompt({ name: 'get-help' });
    return {
      capabilities: pair.client.getServerCapabilities(),
      instructions: pair.client.getInstructions(),
      tools,
      prompts,
      resourceTemplates,
      help,
    };
  } finally {
    await pair.close();
  }
}

describe('Advertised MCP contract', () => {
  before(async () => {
    tmpDir = await createTestRoot();
  });

  after(async () => {
    await cleanupTestRoot(tmpDir);
  });

  it('CONTRACT-001: full server surface matches the snapshot', async (t) => {
    const value = await surface(false);
    assert.ok(
      !JSON.stringify(value).includes('fsmcp-test-'),
      'surface must not embed the test root',
    );
    t.assert.snapshot(value);
  });

  it('CONTRACT-002: --read-only surface matches the snapshot', async (t) => {
    const value = await surface(true);
    assert.ok(
      !JSON.stringify(value).includes('fsmcp-test-'),
      'surface must not embed the test root',
    );
    t.assert.snapshot(value);
  });
});
```

Notes:

- Do **not** include `getServerVersion()`. The version changes on every
  release, and the snapshot would churn for no reason.
- Both modes advertise the same capabilities, so `listPrompts()`,
  `listResourceTemplates()` and `getPrompt` succeed in read-only mode too
  (verified at planning). If one throws, STOP.

## STOP conditions

Stop and report back (do not improvise) if:

- The snapshot contains an absolute path or a platform-specific string, so
  it would differ between the Windows and Ubuntu CI legs. Report the field.
  Normalising it is a design decision.
- Two consecutive runs on the same machine give different snapshots, which
  means non-deterministic ordering in the contract. Report which key
  reorders.
- The snapshot shows a `$ref`/`$defs`, or a tool advertised in read-only mode
  that `MUTATING_TOOL_NAMES` (`src/tools/index.ts`) lists. That is a product
  bug, so report it.
- `t.assert.snapshot` is unavailable (`node --version` is not 24.x).
